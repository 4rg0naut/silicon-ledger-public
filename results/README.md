## Cross-experiment conclusions (current)
1. **The ANE is real, usable and measured** on this M4 — three independent signals agree
   (hardware intervals, GPU draw at zero, throughput).
2. **The ANE's advantage is efficiency, not just speed** — 5.6× vs 2.3×.
3. **Apple's on-device LLM is usable but shaped differently than assumed**: its
   load cost is cold-start only, and a resident server is not faster than one-shot.
4. **Dense transformer ops are the ANE's home turf** — so encoders (embeddings)
   are a better fit than anything with scatter/RNN/control flow.
5. **"Prefer the ANE" is not "use the ANE"** (EXP-004): Core AI's
   `preferredComputeUnitKind: .neuralEngine` fell back to the **GPU** (GPU rail 4421.6 mW,
   ANE rail 0.0 mW) — and it did so *while being faster and more deterministic than the
   explicit `.gpu` preference*, so neither speed nor jitter reveals placement. Verify
   placement with the power rails; `ane-hw-intervals` is blind to Core AI graphs.
6. **The ANE is reachable, and two things decide it** (EXP-005): **dtype** (fp32 → 0 ANE
   regions, fp16 → 14 — Apple: *"fp32 falls back to GPU/CPU"*) and **fp32 ops inside the
   graph** (removing the fp32 softmax and fp32 pooling took GPU power 333 → 83 mW and warm
   median 13.14 → 4.00 ms, beating the published fp32 GPU path outright). But **"on the ANE"
   ≠ "good on the ANE"**: fp16 alone put it on the ANE and made it 3× slower. And **region
   count is a shape metric, not a quality metric** — fewer regions meant fewer ANE↔GPU
   boundaries, not less ANE work (F-26).

## Conventions for a new experiment
```
results/EXP-NNN-short-slug/
  README.md     <- question, method (exact commands), numbers, caveats, artifacts
  raw/          <- traces, logs, CSVs — the raw evidence, never edited
```
Rules:
1. Record the **exact commands** — a result nobody can reproduce is not a result.
2. State **caveats and unknowns** explicitly; do not launder vendor claims into ours.
3. If a measurement contradicts an earlier one, **say so in both records** rather
   than silently editing (see EXP-001's `conv` correction).
4. Keep raw artifacts; they are the only defence against a mis-parsed number.
