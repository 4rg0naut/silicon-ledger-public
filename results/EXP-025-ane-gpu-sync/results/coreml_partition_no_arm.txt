So even the ANE+CPU partitioned model attaches events with signal value 0 and NONE of its 8
counters moves across 22,715 polls. The events are structural (attached to every request) but
never armed for these workloads.

CONCLUSION
----------
Core ML on this box does not co-schedule ANE and GPU: eligible graphs go entirely to one engine
(ANE with cpuAndNeuralEngine; GPU with all); the only split observed is ANE+CPU, and CPU-side
segments do not arm the shared-event counters. The live ANE<->GPU shared-event handoff therefore
remains unobserved in-process with the models available here. The probe (join_chain.dylib) is
ready to capture and poll the chain the moment a model that Core ML genuinely runs on ANE+GPU is
available; on this evidence that model is not one of the local FluidAudio/bench/zoo set, nor one
Core ML will synthesize from an eligible conv graph (GOTCHAS-074).
